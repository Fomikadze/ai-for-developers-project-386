# API и генерация клиента

Обязательная часть работы с API: TypeSpec-контракт, сгенерированная OpenAPI-спецификация и клиентский SDK для фронтенда.

- Цепочка: `typespec/main.tsp` → `tsp compile` → `typespec/openapi.yaml` → `@hey-api/openapi-ts` → SDK в `frontend/src/api/generated/`.
- Для языка фронтенда (TypeScript) генератор клиента из OpenAPI существует (`@hey-api/openapi-ts`), это проверено до выбора стека.
- Серверный генератор не используется: бэкенд на Ktor реализуется вручную по контракту и проверяется тестами на `testApplication`, которые покрывают сценарии контракта.
- `openapi.yaml` коммитится в репозиторий. SDK генерируется скриптом `pnpm generate` (`mise run sdk`) и не коммитится: `frontend/src/api/generated/` добавлен в `.gitignore` и исключён из ESLint и Prettier. Компоненты импортируют клиент только оттуда.

## Эндпоинты (черновик, уточняется в контракте)

| Метод | Путь | Назначение | Ошибки |
| --- | --- | --- | --- |
| `GET` | `/api/health` | проверка, что приложение работает (для smoke-теста) | |
| `GET` | `/api/owner` | данные владельца: `name`, `title`, `avatarUrl` (может быть `null`) | |
| `GET` | `/api/meeting-types` | список типов встреч | |
| `POST` | `/api/meeting-types` | создать тип встречи (владелец) | `400` |
| `GET` | `/api/meeting-types/{id}/slots` | только свободные слоты на всё окно записи, по возрастанию `start`; занятые не возвращаются | `404` |
| `POST` | `/api/bookings` | создать бронь (`meetingTypeId`, `start`, `guestName`, `guestEmail`, `guestPhone`, `notes`) | `400`, `404`, `409` |
| `GET` | `/api/bookings/upcoming` | предстоящие встречи всех типов с данными гостя и `notes` (владелец) | |

## Заметки к брони

- `notes` — необязательная строка, до 500 символов. Пустая строка приравнивается к отсутствию заметки.
- Превышение длины — `400 VALIDATION_ERROR`.

## Ошибки

Любой ответ с ошибкой имеет тело `{ "code": string, "message": string }`. `code` — машиночитаемый код из списка ниже, по нему фронтенд показывает перевод. `message` — текст для отладки на английском, пользователю не показывается.

| HTTP | `code` | Когда |
| --- | --- | --- |
| `400` | `VALIDATION_ERROR` | невалидные поля запроса |
| `400` | `INVALID_PHONE` | телефон не в формате E.164 |
| `400` | `SLOT_OUT_OF_RANGE` | слот вне окна записи, вне рабочих часов или не на шаге стартов |
| `404` | `MEETING_TYPE_NOT_FOUND` | тип встречи не найден |
| `409` | `SLOT_TAKEN` | слот пересекается с существующей бронью |

Это единственный список кодов ошибок. Новый код добавляется сюда, в контракт и в оба файла переводов.

## Телефон

- Мобильный телефон хранится и передаётся в формате E.164: `+` и код страны, затем номер, без пробелов, скобок и дефисов, не более 15 цифр.
- Регулярное выражение: `^\+[1-9]\d{6,14}$`. Поле обязательное.
- Правило задаётся в TypeSpec (`@pattern`), проверяется на бэкенде (`400`) и на фронтенде. Фронтенд допускает ввод с форматированием и приводит номер к E.164 перед отправкой.
