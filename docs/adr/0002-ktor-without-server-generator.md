# Бэкенд на Ktor пишется вручную по контракту, без серверного генератора

Источник правды — контракт `typespec/main.tsp`, из него генерируется `openapi.yaml` и клиентский SDK фронтенда. Серверный код из OpenAPI не генерируется: роуты Ktor пишутся вручную и проверяются тестами на `testApplication`, которые покрывают каждый случай ошибок и порядок проверок из `docs/api.md`. Так архитектура бэкенда (Clean Architecture и CQRS, обработчики за интерфейсами) не подстраивается под форму сгенерированного кода.

## Considered Options

- **Серверный генератор OpenAPI для Kotlin.** Роуты и DTO совпадали бы с контрактом автоматически. Отклонено: сгенерированные интерфейсы плохо ложатся на слои и обработчики команд и запросов, а расхождение с контрактом всё равно нужно ловить тестами.

## Consequences

- Расхождение кода с контрактом обнаруживают только тесты. Паттерны полей и список кодов ошибок в Kotlin дополнительно сверяются с `openapi.yaml` отдельными тестами.
- Любое изменение API идёт по цепочке: контракт, `openapi.yaml`, бэкенд и тесты, SDK, фронтенд.
